# Contributing

## Review Standard

Every contribution must be:
- **Testable** — includes steps to test the change
- **Evidenced** — shows before/after proof or references source material
- **Constrained** — complies with `docs/SEALED_LAW.md` and `docs/PUBLIC_VS_INTERNAL_NAMING.md`

## What We Accept

- Documentation corrections with evidence of the gap
- Test additions that prove or challenge claims
- Case submissions with public sources
- Proof extensions with formal specification
- Language corrections aligned with sealed law

## What We Reject

- Identity claims without proof chains
- Internal operating names used as public product language
- Badge-style claims (verified, certified, trusted, guaranteed, secure)
- Secrets, infrastructure details, or operator-specific paths
- Changes that bypass the sealed law

## Language Rules

Every public sentence must answer one of:
- What is the method?
- What is the mechanism?
- What is the proof?
- What is the case?
- What failed?
- What was tested?
- What can be challenged?
- What can be improved?

If a sentence only sounds impressive but does not answer one of those, remove it.

## How to Submit

1. Fork the repo
2. Create a branch: `contribution/<topic>`
3. Make changes with evidence
4. Submit PR with: purpose, what changed, how it was tested
5. All AI-generated content must pass `docs/AI_REVIEW_PROTOCOL.md` review

## Banned Words in Headlines

Never lead with: verified, certified, trusted, guaranteed, secure, confirmed, validated by us

Prefer: proved, enforced, constrained, modeled, tested, recorded, evidenced, challenged, simulated
